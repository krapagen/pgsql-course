# Самопроверка после собственной попытки

Здесь находятся один вариант решения и SQL-пробы для каждой стадии. Они показывают поведение модели; другая корректная схема может потребовать адаптации имён ограничений в проверках.

- `01-protect.sql` — ключи и составная ссылка с NOT VALID.
- `02-repair.sql`, `repair-core.sql` — первое исправление, подтверждённый повтор и остановка при противоречии, затем VALIDATE. Временная функция в core — форма записи эталона; в своём решении можно использовать DO или другой транзакционный SQL.
- `03-expand.sql` — новое представление для совместной работы версий.
- `04-cutover.sql` — финальная сверка и переключение обязательности.
- `05-rollback.sql` — возврат old-only операций без потери бизнес-ограничений.
- `queries.sql` — диагностические запросы, выполнять отдельно на нужной стадии.
- `checks-*.sql` — пробы исходной, защищённой, исправленной, переходной и возвращённой модели; отказ аудита и противоречия.
- `run.sql` — весь эталон на отдельной пустой базе, включая повтор ремонта и возврат.

## Посмотреть отдельную стадию

Сравните соответствующий файл со своим решением. Проверки `checks-*.sql` работают в BEGIN/ROLLBACK и не сохраняют тестовые изменения. Решения меняют схему и данные; стадии 01/03/04/05 повторно поверх применённых не запускайте. Стадия 02 специально допускает подтверждённый повтор.

## Воспроизвести эталон целиком

Из корня пакета при запущенном Compose создайте другую пустую базу:

```sh
docker compose exec -T postgres createdb -U course course_hw04_reference
docker compose exec -T postgres psql -X -U course -d course_hw04_reference -v ON_ERROR_STOP=1 -f /work/self-check/run.sql
```

Своя работа в course_hw04 сохранится. Для ещё одного прогона выберите новое имя базы в обеих командах. Эталон существующую базу не очищает. Для установленного PostgreSQL можно выполнить `psql -X -d ИМЯ_ПУСТОЙ_БАЗЫ -v ON_ERROR_STOP=1 -f self-check/run.sql`.

Сообщения OK и OK SQLSTATE описывают SQL-пробы. При неожиданном поведении скрипт останавливается. Он не проверяет обоснование решений или фактическую остановку внешнего импорта. Служебные аварийные пробы вызывают ту же функцию ремонта, которую использует 02-repair.sql, внутри откатываемых подопераций.
