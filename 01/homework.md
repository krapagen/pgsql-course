# Домашнее задание 1 PostgreSQL и реляционные базы данных

**Ориентировочное время — 60 минут** при установленном Docker с Docker Compose либо доступной PostgreSQL. Завершите схему сервиса записи на курсы, загрузите готовые данные и выполните SQL-запросы.

Все нужные файлы находятся в этой папке. Команды выполняйте из папки с `compose.yaml`. Инструкция подключения — в [README](README.md), заготовка схемы — [schema.sql](schema.sql), исходные данные — [seed.sql](seed.sql). Свои запросы удобно писать в [queries.sql](queries.sql).

## Кейс и правила

В сервисе есть пользователи `users`, курсы `courses` и регистрации `enrollments`. Один пользователь может участвовать в нескольких курсах, у курса может быть несколько участников.

Регистрация хранит сумму в копейках, статус и момент создания. Валюта — рубль; бесплатная регистрация допустима.

- Каждая регистрация обязательно относится к существующим пользователю и курсу.
- На пару пользователь и курс разрешена одна регистрация, включая отменённую. Повторное обращение меняет существующую запись.
- Сумма обязательна и неотрицательна.
- Статус обязателен: `pending`, `paid` или `cancelled`. По умолчанию — `pending`.

## Шаг 1 Запустить стенд

В папке пакета выполните:

```sh
docker compose up -d --wait
docker compose exec -T postgres psql -X -U course -d course_hw01 -c 'SELECT version(), current_database(), current_user;'
```

Пользователь — `course`, база — `course_hw01`. Отдельный SQL-клиент устанавливать не нужно. Если используете свою PostgreSQL, создайте отдельную пустую базу и выполняйте SQL в привычном клиенте.

## Шаг 2 Завершить схему

Откройте `schema.sql`. Таблицы пользователей и курсов уже описаны. В `enrollments` добавьте обязательность значений, внешние ключи, уникальность пары и проверки суммы и статуса по правилам кейса.

PK по `id`, типы полей и значения по умолчанию заданы в заготовке. Завершите ограничения до первого применения схемы, затем выполните:

```sh
docker compose cp schema.sql postgres:/tmp/schema.sql
docker compose exec -T postgres psql -X -U course -d course_hw01 -v ON_ERROR_STOP=1 -f /tmp/schema.sql
```

Для повторного прогона после изменения уже применённой схемы используйте другую пустую базу. Порядок действий есть в README.

## Шаг 3 Загрузить данные

Готовый `seed.sql` примените один раз после создания схемы:

```sh
docker compose cp seed.sql postgres:/tmp/seed.sql
docker compose exec -T postgres psql -X -U course -d course_hw01 -v ON_ERROR_STOP=1 -f /tmp/seed.sql
```

В базе будут 3 пользователя, 2 курса и 3 регистрации. Вера существует, но регистраций у неё нет.

| Пользователь | Курс | Сумма, коп. | Статус |
| --- | --- | ---: | --- |
| anna@example.test | postgres-dev | 150000 | paid |
| anna@example.test | sql-basics | 50000 | pending |
| boris@example.test | postgres-dev | 150000 | cancelled |

## Шаг 4 Написать три SELECT

Самостоятельно напишите и выполните запросы:

1. Вывести email пользователя, код курса и статус каждой регистрации. Упорядочить по email и коду курса.
2. Вывести email пользователя и код курса для оплаченных регистраций.
3. Вывести email пользователей, у которых нет регистраций.

Первый запрос связывает три таблицы. Для третьего можно использовать `LEFT JOIN` с проверкой отсутствия связанной строки либо `NOT EXISTS`.

Для интерактивной работы:

```sh
docker compose exec postgres psql -X -U course -d course_hw01
```

Выход из psql — `\q`.

## Шаг 5 Выполнить некорректные вставки

Напишите и выполните три отдельные попытки INSERT:

1. Повторно зарегистрировать Анну на `postgres-dev` с допустимой суммой и статусом.
2. Зарегистрировать отсутствующего пользователя с ID `-1` на существующий `postgres-dev`; остальные значения должны быть допустимы.
3. Зарегистрировать Веру на `sql-basics` с суммой `-100` и статусом `pending`.

Найдите ID существующих родителей через SELECT по email и коду курса. Выполняйте попытки по одной в autocommit, без общего BEGIN/COMMIT. Прочитайте сообщения PostgreSQL и определите, какое правило вызывает каждый отказ.

После попыток посмотрите, сколько строк осталось в `enrollments`.
