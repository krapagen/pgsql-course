# SQL для самопроверки

Используйте эти файлы после самостоятельного выполнения. Пояснения и ожидаемые результаты находятся в [ключе](../answer-key.md).

- [reader.sql](reader.sql) — открытие снимка в A; подключение нужно оставить открытым.
- [queries.sql](queries.sql) — решения двух UPDATE и DELETE с замерами; выполняются в B с autocommit на свежих данных.
- [vacuum.sql](vacuum.sql) — дополнительный опыт: диагностика A, очистка и замеры; выполняется в B вне транзакции.

Для полного повторения создайте новую пустую базу по README пакета, примените схему и seed и откройте A и B. Скопируйте файлы в контейнер:

```sh
docker compose cp self-check postgres:/tmp/self-check
```

В интерактивном psql A выполните `\i /tmp/self-check/reader.sql`. В B выполните `\i /tmp/self-check/queries.sql`. A пока видит 30 000 строк и progress 20; B — 21 000 и 22.

Для дополнительной части запустите в B `\i /tmp/self-check/vacuum.sql`, затем выполните `COMMIT;` в A и повторите тот же файл в B. После второй очистки проверьте новое чтение A. В конце восстановите autovacuum по заданию и выйдите из обоих psql.

Не запускайте `reader.sql` через одноразовое подключение `psql -f`: его закрытие освободит снимок. Сравнивайте результаты и объяснение; точные байты и физические адреса могут отличаться.
